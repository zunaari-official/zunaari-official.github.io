# 公開用データとページ生成

このフォルダ（`_src/`）と `_build/` は GitHub Pages では配信されません（名前が `_` で始まるフォルダは公開ページに含まれない）。ただしリポジトリは公開なので、**ここに置くものはすべて誰でも読める**前提で扱います。

## ファイル

| ファイル | 内容 |
|---|---|
| `data/catalog.json` | 公開用データ（楽曲・音源・リリース・収録枠・動画・Homeの掲載設定）。許可した項目だけを持つ |
| `build.config.json` | 生成するページの範囲（`"all"` または slug の一覧）と試作モード（`preview: true` のページは検索エンジンに登録しない） |
| `../_build/build.mjs` | 生成スクリプト（Node.js 18以上、依存パッケージなし） |

## 使い方

```sh
node _build/build.mjs          # データを検査してから生成する
node _build/build.mjs --check  # 生成結果とファイルが一致するかだけを確認する（書き込まない）
node _build/build.mjs --root <作業コピー> --production  # 本番用の出力を作業コピーに作る（noindex なし、sitemap に全ページ）
```

`--production` は `--root` で作業コピーを指定したときだけ使えます（リポジトリ自体は `build.config.json` の設定どおりに保つため）。

検査で問題があると、ファイルを1つも書き込まずに止まります。

生成されるもの：

- `index.html` のうち、`<!-- generated:… -->` と `<!-- /generated:… -->` の間（メインメニュー、Latest、Releases の一覧）。その外側は手で編集してよい
- `music/`・`releases/` 以下の各ページ、`404.html`、`sitemap.xml`、`robots.txt`（直接編集しない。データを直して再生成する）
- 試作モード（`preview: true`）では、子ページと404に noindex を付け、`sitemap.xml` には Home だけを載せる

## データの決まり

- 1つの音源が複数のリリースに入っているときは、音源を1つだけ登録し、各リリースの収録枠から参照する。
- 音源の `title` は、楽曲名と違うとき（例：`(AIRI Chapter)`）だけ書く。同じ情報を2か所に持たない。
- 名義（`displayArtist`）は配信先の表記に合わせる。複数のときは `, ` で区切り、それぞれ `artists` に登録した名前と一致させる（一致しないと検査で止まる）。
- 動画の `kind` は確認できたものだけ書く。`official-music-video`（公式MV。「MVを見る」）、`audio`（配信版と同じ音源と確認した動画。「YouTubeで聴く」）、`null`（未分類。ページには出さない）。
- ページには「初出」を出さない。配信日は収録先ごと、YouTube公開日は動画ごとに表示する。
- 確認できていない分類（ジャンル・シリーズ・歌唱言語・参加者の役割）は書かない。空欄のものは一覧の絞り込みに出ない。
- 内部の管理番号・制作に関する情報・公開前の作品は入れない（検査で一部を自動検出する）。
